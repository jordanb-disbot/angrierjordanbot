# Server activity logging

The activity feed is independent of Security, Moderation, and Jail. It is disabled unless the main worker has `ENABLE_ACTIVITY_LOGGING_SMOKE=true`. It uses the existing `channels.staff_log` mapping, which the one-shot maintenance command maps to `📋-the-clipboard` (`1538321358310867104`).

Run `node scripts/enable-production-activity-logging.mjs` through the Railway **maintenance** service first. Set `ACTIVITY_LOGGING_DRY_RUN=true` on maintenance for a read-only preflight, then remove it for the applying run. The script verifies the production target, private database, channel, category, bot send access, and admin-only view access. It writes only `channels.staff_log` through audited `ConfigService`, and only if the mapping differs. After the PASS lines, add `ENABLE_ACTIVITY_LOGGING_SMOKE=true` to the **main** worker and redeploy it. Worker startup repeats the privacy and send-access check; a failed check leaves the worker unready instead of publishing logs to an unsafe channel.

The feed records message edits and deletions, bulk deletions, member joins/leaves, role/nickname/timeout changes, bans/unbans, voice joins/leaves/moves, channel and role changes, and Discord audit entries. It does not copy every ordinary new message. It excludes the log channel and suppresses mentions in posted cards. Recent message text is held in a bounded, 24-hour in-memory cache for edit/delete context. If Discord did not deliver the original content, or the worker restarted before a deletion, the card says the text is unavailable; it does not invent missing text. This cache is not a durable message archive.

Join/leave a voice channel, add/remove a test role, and verify cards. Verify a non-admin cannot view Clipboard. Ensure ordinary new messages do not produce cards. Disable the worker flag to stop the feed without changing its channel mapping.
