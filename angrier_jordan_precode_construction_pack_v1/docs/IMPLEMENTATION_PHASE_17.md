# Phase 17 — Persistent channel games

Counting and Last Letter use the existing versioned ChannelGameState table and shared serializable operation receipts. Game state, wins, public delivery jobs and restoration audits commit together. Message retries cannot double-score or duplicate wins. No migration or normal-play slash command is added. Both use their configured channels and remain disabled behind features.channel_games / ENABLE_CHANNEL_GAMES_SMOKE.

Counting accepts integer posts with exact arbitrary-precision arithmetic. Non-number conversation is ignored. A wrong number or consecutive turn resets the next number to 1, publicly identifies the breaker and previous valid count, and offers a staff-only restoration control. Recliner+ restoration requires the unchanged reset version, restores the preceding member/count/awarded milestone state, and writes an audit entry. A later valid post invalidates the old restoration control. Every exact 100 milestone earns one Counting Win and counting continues. There is no replay control.

Last Letter validates a single English word, then checks the previous ending letter, duplicate history and alternating valid members. Invalid attempts score −1 without changing the chain; valid words score +1 or +2 when their first and last letters match. Scores may be negative. Reaching 50 increments Last Letter Wins once and atomically creates the next empty round. There is no replay control.

Word validation uses pinned dictionary-en and nspell packages, with their distributed licenses retained in dependencies. The [dictionary source](https://github.com/wooorm/dictionaries/tree/main/dictionaries/en) supplies English inflection rules; [nspell](https://github.com/wooorm/nspell) evaluates them locally. Runtime makes no dictionary network request. Lowercase lookup rejects capitalization-only names; a word that is also a common noun remains valid in its ordinary meaning. An explicit abbreviation denylist and common gaming/adult slang supplement cover the contract's exceptions. Username syntax, multi-word input and invented words are rejected. The lexicon is deterministic and versioned with the lockfile; no generative word judgment is used.

Public delivery uses shared persisted DeliveryEngine jobs and safe mention restrictions. Milestone/winner images reuse the frozen lounge frame, fonts and colors. Configuration and permission checks run before state writes. Mandatory live Discord acceptance remains pending.

Tests cover race/replay, reset/restoration, milestone award atomicity, negative scores, dictionary classes, duplicate/consecutive words, automatic win/reset, flag/channel restrictions and staff authorization. See testing/runtime/channel-games.test.mjs, testing/adapters/channel-games.test.mjs and testing/postgres/channel-games.test.mjs. Execution status is recorded in IMPLEMENTATION_STATUS.json rather than inferred from test presence.
