# Phase 18 — Crime, restitution and crime jail

Implements the existing `/crime rob`, `/crime 911`, `/crime wanted` and `/crime bail` contracts with Crime disabled by default. Robbery and controls use current member/channel access, shared capability/security eligibility and persisted jail restrictions. `/crime 911` selects a current incident; `/crime bail` selects a member then requires confirmation of the saved exact bail amount. No new slash options are needed.

Canonical boundaries are fixed: 30-minute robber cooldown, 60-minute victim protection after any valid attempt, 60-second victim Fight Back, 180-second witness reports, and 24-hour crime jail unless bailed. Theft is a bounded percentage of the victim’s Wallet, capped to its available unheld amount. The Bank is never stolen. Failed attempts still consume cooldown/protection and increase Wanted; failed Fight Back adds no loss.

Successful theft credits the robber’s Wallet immediately through the shared LedgerEngine. Shared wallet holds reserve exactly those credited proceeds for the unresolved restitution window. This keeps the canonical wallet transfer while preventing spending, depositing, wagering or transferring the funds before a guaranteed refund can be honored. Successful Fight Back releases the hold and returns all stolen funds immediately. Arrest does the same if they were not already returned. A clean close releases the hold to become spendable. No settlement mints money or draws from the robber’s Bank; Fight Back followed by arrest cannot pay a second refund.

Each eligible witness gets one durable shared Vote per incident; robber and victim cannot report. Multiple reports increase capped catch risk. Outcome rolls and the policy are sampled/stored with the original incident, kept out of public projections, and survive restart. Successful robberies resolve arrest risk after the witness window; failed attempts resolve their base catch risk immediately. Every accepted consequential operation uses shared serializable operation receipts, SessionEngine, TimerEngine, ledger, holds, VotingEngine and audit services. Persisted jobs handle close, heat decay, crime release and shared record publication.

Wanted uses Clean → Suspicious → Wanted → Most Wanted → Public Enemy at heat 0/10/30/60/100, capped at 100. Configurable defaults add 10 heat per attempt and another 10 on success, and decay 10 per hour. Dedicated `heatDecayedAt` preserves fractional hours and prevents unrelated protection/cooldown writes from restarting decay. Arrest resets Wanted to Clean. These numeric heat/probability/bail defaults are ordinary implementation choices for unspecified values, not additional owner-locked product decisions.

Default probabilities: robbery success 45%; theft 10–25% of Wallet; Fight Back 50%; catch base 10% plus 0.5 percentage points per heat point, 10 percentage points per witness, and 15 percentage points for successful Fight Back, capped at 85%. Default bail is 100 + 2×heat + stolen amount + uniform 0–100 Ottomans. Individual generated dashboard settings validate basis points, percentage bounds, positive heat rates and bounded bail coefficients. An incident snapshots its probability/bail policy; timers and protected Bank remain canonical.

Crime jail uses the shared `JailSentence` model with type `CRIME`, independent of moderation Hotseat. Bail debits available Wallet then Bank atomically and clears only the quoted crime sentence. Moderation restrictions remain. Crime-only members may initiate bail, including for themselves; all ordinary commands/components remain confined through the global runtime guard. Passive receipts and already scheduled settlements remain unaffected. Crime expiry honors existing leave-pause/rejoin-resume fields and never clears another sentence. Public shared jail roster and status include crime sentences.

Arrest renders a public mugshot card in the frozen event window with Space Grotesk/Inter and the member’s Discord avatar when available; deterministic initials serve as an offline fallback. Public responses disable automatic mentions. Renderers never receive the private catch/Fight Back/random bail rolls. Gate B requires owner presentation review; live Discord acceptance remains pending.

Dependencies: migration `0017_wallet_holds` and shared ledger enforcement, migration `0018_crime_decay`, Crime settings/capability/help/tutorial metadata, central confinement guard and `crime.close`, `crime.release`, `crime.decay`, `crime.records`, `crime.publish`, `crime.refresh` scheduler wiring. Publication uses the shared DeliveryEngine to reconcile uncertain sends without duplicate incident cards; bail/expiry queue refreshes so the mugshot reflects release. Crime-specific wins/failures feed existing profile counters; `crime.robberies` and `crime.largest_theft` use the shared record engine.

Targeted tests cover exact deadlines, wallet-only theft and holds, concurrent victim protection/cooldowns, Fight Back→arrest single restitution, witness uniqueness, randomized bounded risk/bail, concurrent bail, moderation/Crime union, automatic heat decay, paused/resumed expiry, restart and receipt replay. Validation results are recorded only after execution; current feature remains disabled pending integration and acceptance.
