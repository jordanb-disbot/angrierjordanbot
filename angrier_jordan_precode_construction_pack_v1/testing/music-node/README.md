# Test node source contract

This is an unlaunched test template, not a live playback verification or production deployment. Runtime music stays disabled until the owner accepts its remaining gates. The latest owner decision selects multi-source Lavalink playback through maintained YouTube and SoundCloud support. Direct catalog audio is optional.

## Reviewed releases

The official release pages identify [Lavalink 4.2.2](https://github.com/lavalink-devs/Lavalink/releases/tag/4.2.2), [youtube-source 1.18.2](https://github.com/lavalink-devs/youtube-source/releases/tag/1.18.2), and [LavaSrc 4.8.3](https://github.com/topi314/LavaSrc/releases/tag/4.8.3). These are released versions, not inferred snapshot versions. The tagged build files establish the exact reported plugin names [youtube-plugin](https://github.com/lavalink-devs/youtube-source/blob/1.18.2/plugin/build.gradle.kts) and [lavasrc-plugin](https://github.com/topi314/LavaSrc/blob/4.8.3/plugin/build.gradle.kts). Maven coordinates are `dev.lavalink.youtube:youtube-plugin:1.18.2` and `com.github.topi314.lavasrc:lavasrc-plugin:4.8.3`, using `https://maven.lavalink.dev/releases` with snapshots disabled. Maven directory requests were intermittently unavailable during research; no artifact download, checksum verification, JVM launch, or live provider playback was performed.

The [YouTube plugin configuration](https://github.com/lavalink-devs/youtube-source/blob/1.18.2/README.md#plugin) requires disabling Lavalink's built-in YouTube source. The template enables the maintained plugin and the built-in SoundCloud manager, and disables unrelated built-in sources. It uses the documented client order and does not configure OAuth, cookies, generated proof tokens, remote cipher services, or yt-dlp. Provider availability still needs a live test; this configuration is not evidence that all clients currently play successfully.

## Optional metadata sources

Spotify and Apple Music remain off in this template. An operator may add the pinned LavaSrc dependency and explicitly enable either manager only after supplying authorized provider application credentials through private deployment secrets. Spotify uses its developer client ID/secret, not account cookies or an anonymous token service. Apple uses authorized MusicKit credentials, not a token copied from a web bundle. Keep every other LavaSrc source and lyrics source disabled, including its separate YouTube/yt-dlp managers. Configure `plugins.lavasrc.providers: []` as defense in depth; the application never submits its mirror tracks for playback. Do not expose LavaSrc's runtime configuration endpoint to members. These options and credentials are described in the [tagged LavaSrc configuration](https://github.com/topi314/LavaSrc/blob/4.8.3/README.md#configuration).

LavaSrc's [mirroring track implementation](https://github.com/topi314/LavaSrc/blob/4.8.3/main/src/main/java/com/github/topi314/lavasrc/mirror/MirroringAudioTrack.java) performs its fallback lookup during playback and may select the first result. Consequently, our boundary discards all Spotify/Apple encoded tracks. The application matches their public metadata against YouTube/SoundCloud, then freshly loads the selected public recording identity. No preview or mirror capability escapes the metadata lookup.

## Application enforcement

`LavalinkRestClient` structurally implements `MusicResolutionProvider`. Its default policy is `{mode:'multi-source'}`. Before lookup, `/v4/info` must report major version 4, exactly `youtube` and `soundcloud`, and exactly `youtube-plugin` version `1.18.2`. Optional `metadataSources:['spotify','applemusic']` adds exactly those managers plus `lavasrc-plugin` version `4.8.3`. This policy is explicit operator configuration; it does not obtain credentials or enable node plugins. A successful preflight is cached only within the immutable ready-session client. Recreate the client after node/session changes and do not mutate node source configuration while a client is active.

The [Lavalink info endpoint](https://lavalink.dev/api/rest.html#get-lavalink-info) reports loaded source managers and plugins. It does not prove their private configuration, artifact integrity, credentials, DNS, redirect targets, or network egress safety. Trusted node deployment must enforce those controls and keep its authenticated REST API private. A reviewed plugin version change requires updating the template and application allowlist together.

`search` owns the `ytmsearch:`, `ytsearch:`, and `scsearch:` prefixes. `resolve` accepts canonical public provider URLs only. Both return projected metadata, never encoded tracks, plugin objects, credentials, or transient stream URLs. Public artwork has a separate HTTPS CDN allowlist and refuses query-bearing URLs. `loadPlayableTrack` accepts only selected YouTube/SoundCloud track identities and returns a process-local opaque handle; the newly loaded result must match the selected public identity. Playlist results lacking a reliable upstream total are marked partial. The 128 KiB response bound remains deliberate; oversized collections fail safely rather than silently appearing complete.

An explicitly enabled `{mode:'multi-source',catalog:true}` additionally permits `http` only with a trusted catalog resolver. `{mode:'direct-only'}` remains available for isolated catalog nodes/tests and requires exactly `http` with no plugins. Catalog deployment must restrict source DNS/redirect/egress to authorized origins, including rebinding/private-address controls. Neither mode accepts arbitrary member audio URIs or search prefixes in catalog IDs.

The template binds localhost. Local tests require the explicit `allowInsecureHttp` option; other deployments use TLS/private operator routing. Set the node password in a private environment; never commit it. Existing database test credentials remain governed separately by the root `.env.test.local` / `TEST_DATABASE_URL` rules. This change does not create or read any credentials.
